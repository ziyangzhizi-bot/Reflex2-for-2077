# Reflex2—— 中文说明

> ## ⚠️ 最重要的一条(只用记这一条)
> **改完分辨率,不要直接回存档。**
> 正确顺序:**设置里改分辨率 → 先回主菜单 → 再从主菜单读档进游戏**。
> 改完分辨率直接点"返回存档"会在几秒内**闪退**(游戏内 `dxgi` / 渲染侧的问题,和本 mod 的开关无关)。
> 更省事的做法:**进游戏之前就把分辨率设好**,这样全程都不需要切换。
> 换完分辨率后本局扭曲会自动停用(保护措施),**重启游戏**即恢复;面板里的"状态"会直接告诉你现在是哪种情况。
>
> ---

> 用 **NVIDIA latewarp 内核**(`nvngx_latewarp.dll`,NGX feature 15)让 Cyberpunk 2077 的画面产生
> **可见的一帧位移/扭曲**。扭曲**全部由 NVIDIA 的内核完成**,本 mod 不含任何自写的重投影/运动矢量/深度数学。
> 所有开关都在 **ReShade 面板**里,中文标签,拖动滑块即可,不需要记热键,也不需要手改配置文件。

---

## 1. 需要什么

| 项目 | 要求 | 说明 |
|---|---|---|
| 游戏 | Cyberpunk 2077(Steam/GOG/Epic 均可) | 目录要能定位到 `bin\x64` |
| ReShade | **6.8.0(本机实测)**、**带 addon 支持**的 64 位版本 | 本 mod 是 `.addon64` 插件,必须有 addon 支持 |
| 显卡/驱动 | **NVIDIA RTX 40 系或更新** + 较新驱动 | 关键文件 `bin\x64\nvngx_latewarp.dll` 由驱动提供;**实测驱动 617.14**,开发期间更新过一次驱动仍正常 |
| 游戏内设置 | 建议开启 DLSS(超分),关闭帧生成 | **本 mod 与帧生成无关**,也不要指望它做帧生成 |

安装脚本会自己检查上面这些(`.\install.ps1 -SelfCheck`),缺什么会直接告诉你。

## 2. 安装

```powershell
# 1) 先自检(不会动任何文件)
.\install.ps1 -SelfCheck

# 2) 试运行:只打印将要做什么
.\install.ps1 -DryRun

# 3) 正式安装(建议先退出游戏)
.\install.ps1
```

安装脚本做四件事:
1. 把 `routea_warp.addon64` 放进 `bin\x64\`;
2. 把 `routea_switch.fx` / `routea_ui_panel.fx` 放进 `bin\x64\reshade-shaders\Shaders\`;
3. 把引擎侧钩子 `routea_hook.asi` 放进 `bin\x64\plugins\`;
4. 写入默认开关文件 `routea_warp_*.txt`(已存在则不覆盖,`-ForceDefaults` 可强制)。

**所有被覆盖的文件先备份**到 `bin\x64\_fwbackup_<时间戳>\`。卸载:`.\install.ps1 -Uninstall`。

## 3. 使用

1. 启动游戏,按 ReShade 面板热键(默认 `Home`)打开面板;
2. 在效果列表里勾上 **`routea_ui_panel.fx`** —— 中文滑块都在这里:

| 面板项 | 作用 | 默认 |
|---|---|---|
| **扭曲(总开关)** | 关掉 = 插件照常加载但完全不动画面 | 开 |
| **UI 保护阈值** | 越大,越多界面元素被保护(不被扭);越小越激进 | 0.05 |
| **深度截断** | 遮住武器/手臂等近处物体;0 = 关闭 | 0.0 |
| **截断扩张(像素)** | 把上一项的范围向外扩几像素,防止边缘残影 | 2.0 |
| **深度反向** | 深度约定反了的时候打开 | 开 |
| **显示遮罩** | 调试用:直接看"哪些像素被当成 UI" | 关 |

3. 想临时关掉扭曲又不开面板:把 `routea_switch.fx` 的 **“Reflex2: 帧扭曲”** 勾去掉(效果不变红即关闭)。

### 3.1 怎么确认“扭曲真的在工作” + 分辨率切换的正确做法

面板里 `routea_ui_panel.fx` 下面有 **5 个只读状态项**(插件每帧写入,你不用手动改):

| 面板项 | 含义 |
|---|---|
| **[状态] 只读** | `0 未就绪` / **`1 扭曲工作中 ✔`** / **`2 已降级:本局不再扭曲,重启游戏恢复`** / `3 失败:看 routea_warp.log` |
| **[状态] 当前后缓冲宽 / 高** | 插件此刻真正在服务的分辨率 —— 改过分辨率,这里就该变成新值 |
| **[状态] 交换链代号** | 每次分辨率 / 全屏 / HDR 变化 **+1**;它变大过,说明“切换被检测到了” |
| **[状态] 内核已扭曲帧数** | **持续变大 = NVIDIA 内核真的在扭这一局**(唯一算证据的指标) |

**判断方法:状态 = `1` 且“内核已扭曲帧数”在涨 → 扭曲确实在工作。**

**改分辨率的正确做法(按可靠性排序):**
1. **最稳:进游戏之前**就把分辨率设好(桌面 / 启动器 / NVIDIA 面板)→ 再启动游戏。全程状态 `1`,不需要任何切换动作。
2. **游戏内改**:设置里改分辨率 → **回主菜单** → **再读档进游戏**。此时状态会变成 **`2 已降级`**
   (这是故意的保护:换链后本局不再碰任何交换链资源),**重启游戏**后恢复扭曲。
3. **不要**:游戏内改完分辨率**直接回存档** —— 目前这条路仍可能在几秒内闪退(详见下方“已知问题”)。

**驱动兼容性:**本项目在一台 **RTX 4060 Laptop / 617.14** 上开发,开发期间用户更新过一次驱动,
mod 仍然正常工作 —— 说明当前驱动支持所依赖的 `nvngx_latewarp.dll`(NGX feature 15)路径。
换驱动后仍建议先看上一节的**状态面板**:状态不是 `1` 就说明这条路径在新驱动上不成立。

## 4. 日志与崩溃取证

| 文件 | 内容 |
|---|---|
| `bin\x64\routea_warp.log` | 运行日志,**自动轮转到 `routea_warp.old.log`** |
| `bin\x64\fwcrash_1.txt` / `.dmp` | 插件自带的崩溃现场(模块表 + 异常记录 + 调用栈) |

崩溃后把 `fwcrash_1.txt` 发出来即可;用仓库里的工具一条命令就能解出符号:

```powershell
python _re\routeA\fg\lookup_rva.py --pe bin\x64\routea_warp.addon64 --map <发行版附带的.map> --crash bin\x64\fwcrash_1.txt
```

## 5. 已知问题(重要,请先读)

| 现象 | 状态 |
|---|---|
| **切换分辨率 / 全屏 / HDR** | ✅ 按下面的顺序做就不会崩:**进游戏前设好分辨率**(最稳),或**游戏内改完先回主菜单再读档**。改完**直接回存档**会闪退 —— 这是唯一要避免的操作,原因在游戏/DXGI 侧(我们在换链后已完全静默,仍复现)。 |
| HUD **平坦区域**(血条填充、面板底色) | 仍可能被扭。轮廓/文字受保护,纯色块内部会漏 —— 需要"块状涂抹"遮罩,尚未实现。 |
| 画面冻结但游戏继续跑 | 已修:旧版把 `GetDeviceRemovedReason()` 返回的 `0x887A0001`(其实表示设备正常)误判为"设备移除"并永久停止呈现。 |
| 位移是**上一帧**的 | 现在用的是引擎发布的一帧 delta,属于设计现状,不是 bug。 |
| 开帧生成(DLSS-G) | 不支持,也不需要。 |

## 6. 风险声明(发布前必读)

* 这是**注入式** mod(ReShade + `.addon64` + `.asi`)。**联网/反作弊环境请自行评估风险**;
  单机游玩、离线为先。作者不对封号等后果负责。
* 依赖**驱动内部接口**(NGX feature 15 的参数名与语义、Streamline 的 tag 布局)。
  **换驱动版本或游戏大版本后可能失效** —— 失效时插件会退化为"加载但不动画面",而不是崩溃。
* 依赖 ReShade 的 addon API。ReShade 升级后若事件/接口变化,需要重新验证。
* 本发行**不包含**任何竞品反编译资料、不包含游戏本体文件。

## 7. 卸载 / 回退

* `.\install.ps1 -Uninstall`:删掉本 mod 的文件,备份目录保留。
* 手动回退:把 `bin\x64\_fwbackup_<时间戳>\` 里的文件拷回原位。
* 只想"不扭曲但保留插件":面板里关掉总开关,或去掉 `routea_switch.fx` 的勾。

## 变更:路径选项已移除(2026-09-25,用户决定)

`Reflex2: which path`(UI first / Light first)这个组合框**已从项目里删除**:

* 插件现在**只有一条路径** —— LDR 扭曲(改扭显示就绪的帧,再拷进后缓冲),也就是实测通过的那条;
* `routea_switch.fx` 里只剩**一个**控件:总开关;
* 原因:UI first 依赖"游戏把自有帧交给内核"(原地改写)这条通道,而当前游戏/驱动不再提供它
  (`Latewarp.Output ret=0xFFFFFFFF`、`GAMETEX bound=0`),留下这个选项只会让人选了之后什么都看不到;
* 代码里那条分支现在永远不会被置位(`g_uiFirstPath` 恒为 0),不存在两条路同时生效的可能。

延迟说明(如实):这条路径的源帧是**上一帧的显示就绪拷贝**,所以画面比输入**晚一帧**;
亮部保留(HDR 不被钳制),HUD 会跟着一起被扭(面板块 [1] 阈值可调保护程度)。
